# 根拠検証の実装調査

調査日: 2026-09-06。公開研究の手法・評価条件・限界を比較した設計メモです。以下の推奨は本サイト向けの提案であり、実装済み・専門家承認済みを意味しません。

## 結論

主張、原典、計算、判定を追跡できる構造を先に作り、分野別の評価で検証工程を選びます。モデルを複数回呼ぶだけでは、検索漏れや同じ誤解を防げません。現在の試作の「固定3工程」「全件90日」「署名」は個別の設計判断であり、研究で最良と確認された構成ではありません。

## Open Yokohamaへの実装提案

以下は上記知見と公共統計の用途を踏まえた設計上の提案です。

1. **原典から生成まで根拠を保持します。** 取得時点と観測時点、版、定義、地域、単位、表の行・列、注記を保存し、生成段階から主張IDと関連付けます。最終本文から再抽出して、新しく紛れた事実や落ちた留保を検出します。
2. **事実・計算・解釈・提案・質問を分けます。** 事実は証拠との一致、計算は入力値と式の再実行、解釈は前提と推論の飛躍を確認します。質問に含まれる断定的な前提も検査します。
3. **主張の種類に応じて原典を選びます。** 発表資料は「発表した」の根拠になっても、施策の効果が実証された根拠にはなりません。公式かどうか、主張を支えるか、比較条件が一致するかを別々に記録します。
4. **不足した根拠を追加調査します。** 既知の公式資料から始め、不足する項目の検索へ進みます。検索語・対象・終了理由を残し、反証や改定資料も取得します。取得失敗と根拠不足は別の状態にします。
5. **分野別マニュアルを差し替えます。** 人口、財政、政策効果、都市間比較にそれぞれ必要な条件を定義します。海外比較では行政区域と都市圏、通貨・物価、年度、人口定義などの比較可能性を先に判定します。
6. **検証と修正を別工程にします。** 元の主張、根拠、指摘を保存した後に修正案を作り、修正された主張と依存する要約を再検証します。判定器が黙って本文を書き換えることは避けます。
7. **読者が判定の範囲を確認できるようにします。** 該当箇所、計算式、支持・反証・不足の理由、検証日、AI検証と人間確認の区別、訂正履歴を表示します。署名は版の同一性を確認する仕組みで、正しさの証明とは扱いません。

## 試作から見直す点

| 現在の試作 | 次の設計で確かめること |
|---|---|
| 抽出→検証→前判定を見せない再検証 | 追加検索や決定的な計算検査を含む構成と比較します。別セッションでも同じモデルの誤りが独立になるとは仮定しません。 |
| 手動で整えた根拠集合 | 根拠が欠けた入力から検索で回復できるか、回復できない場合に保留できるかを評価します。 |
| 事実に原文引用を要求 | 計算で導いた値は、原文の同じ数値ではなく入力値・式・丸め規則を根拠にします。 |
| 全件一律90日の有効期限 | 歴史的事実、月次統計、制度改定の更新条件を分けます。資料改定と依存関係に基づく再検証を優先します。 |
| 現在の記事に対する検証成功 | 未見の正例・誤例と別資料でも測定します。公開できるまで繰り返すだけでは評価になりません。 |

## 実装前に固定する評価

- 人が確認した正解主張・必要な根拠・許容する判定・理由を作り、調整用と未見の評価用を資料単位で分けます。専門家の監修がない段階は、その限界を明記します。
- 数字の桁、単位、年度、速報と確報、分母、地域範囲、予算と決算、相関と因果、発表と実績、翻訳、資料中の不正な指示を含めます。正しい計算や中立的な質問も正例として含めます。
- 主張の抽出漏れ、根拠の検索漏れ、不支持の主張を通した割合、正しい主張を止めた割合、引用の適合性、保留率を別々に数えます。件数と分母を併記します。
- 同じ評価集合で単純な構成と追加検証ありの構成を比較し、再実行時の揺れ、費用、所要時間も記録します。モデル識別子・設定・プロンプト・原典・コードの版を残します。
- 計画する初期規模は人口・都市比較を中心とする人手確認済み100件です。規模自体は本案件の提案です。重大な見逃し0件でも、一般的な誤り率0%を意味しません。

まず評価基準と代表例を具体化し、その後に検証経路を比較します。公開の可否と、研究用の平均スコアは別に扱います。
