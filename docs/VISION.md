# Open Yokohamaの構想

整理: 2026-09-06。初期構想から、市民向けの公共情報基盤に関係する内容をまとめています。
本書は長期的な方向性です。提供済み機能や達成済みの品質保証を示すものではありません。
実行順は[開発計画](PLAN.md)、現在の実装・検証結果は[状態記録](STATUS.md)、採用構成は[ADR](adr/0001-static-public-data-core.md)を参照してください。

## 目的と対象

横浜の公共情報を「収集 → 構造化 → 接続 → 検証 → 分析」し、市民が暮らしや政策について考え、根拠を確かめられる基盤を作ります。
人口、経済、財政、都市、歴史、行政、政策に関する同じ事実・履歴・出典を、WebとAI向けMCPの両方から利用できるようにします。

中核資産は、機械で読める構造化データと原典へのつながりです。画面やAIモデルが変わっても、横浜について蓄積した知識を再利用できることを目指します。

2026-09-07: このプロジェクトの目的に、横浜市域の公開情報を蓄積するDWHの整備を明記します。
共通基盤に数字・文書上の事実・出典・改定履歴を保持し、open.yokohamaの記事・図表・Webと調査・MCPが参照します。
公開記事は使用したデータ・引用・計算の版を固定し、更新型画面はビルド時の公開版を使います。
現状と目標の差分は[監査](DWH-AUDIT.md)、段階的な移行と受入条件は[DWH設計](DWH-DESIGN.md)にまとめます。共通化の実装は未着手です。

## 市民が解けるようにしたい問い

- 横浜市の人口はどう変わり、出生・死亡・転入・転出はそれぞれどの程度影響していますか。
- どの区で子どもや世帯が増え、暮らしの条件はどう異なりますか。
- 市税収入や子育て予算は長期的にどう変わりましたか。
- 政策は誰がいつ決定し、どの予算で実施され、成果は確認できていますか。
- 神戸・福岡などの都市と、同じ定義の指標で比べると何が違いますか。
- 横浜の都市史や過去の行政判断は、現在の課題にどうつながっていますか。
- 選挙の投票率や集計結果は、時期・地域によってどう変わりましたか。

問いに含まれる仮説を事実として扱わず、確認できない理由や因果関係は未確認として示します。

## 設計原則

1. **原典を優先します。** 説明から主張、引用、出典、原本へ遡れるようにし、AIの生成文章を一次資料として保存しません。
2. **事実・解釈・提案を分けます。** 反証、留保、未確認事項も表示し、解釈を確定した事実に見せません。
3. **時間を保持します。** 観測時点、有効期間、公表日、取得日、改定番号を区別し、訂正前の状態を再現できるようにします。
4. **地理を保持します。** 横浜市と18区から始め、必要な資料が整えば町丁や生活圏へ拡張します。市平均だけで地域を説明しません。
5. **数字の条件を残します。** 値、単位、期間、地域、定義、算出方法、出典、取得日時を組にします。
6. **構造化データを正本にします。** 大量のPDFをLLMに渡すだけでデータ基盤とせず、数値は決定的なパーサーで抽出します。

## 共通データと公開インターフェース

```text
公式資料 → 不変の原本 → 検査済みの構造化データ
                              ├ 公開Web / CSV / JSON
                              └ 読み取り専用MCP
```

WebとMCPで指標の定義・出典・問い合わせ処理を共有します。公開側には検証済みの公開データだけを渡します。
現在の静的配信と更新時処理を基準とし、初期構想の技術候補を導入要件にはしません。
常時DB、専用検索基盤、Graph DB、任意のAI質問機能は、実際の需要・費用・運用条件が整った段階で判断します。

## データモデルの方向性

以下は拡張時の概念モデルです。すべての項目が現在のスキーマに存在するわけではありません。

| 対象 | 残す情報・関係 |
|---|---|
| Geography | 地域ID、種別、名称、親地域、自治体コード、境界、有効期間 |
| Source | 提供者、資料名、原典URL、資料種別、利用条件、公表日、取得日 |
| SourceSnapshot | 出典ID、内容ハッシュ、保存先、形式、パーサー版、取得日 |
| Citation | 原本の版、ページ、節、表、行、セル、引用箇所 |
| Claim | 主張、事実・解釈・提案の区分、検証状態、有効期間、支持・反証の引用 |
| MetricDefinition | 指標ID、名称、説明、単位、定義、算出方法、資料系列 |
| Observation | 指標、地域、期間、値、原本の版、改定番号 |
| Issue | 課題、概要、状態、重要性、緊急性、時間軸、関連する事実 |
| Policy | 政策、提案主体、目的、仕組み、状態、実施期間 |
| BudgetProgram | 年度、会計、部局、事業、予算、決算、財源 |
| Decision | 決定主体、日付、議題、種別、結果、政策・予算・課題との関係 |
| Election / ElectionResult | 選挙種別、日付、地域、投票率、候補者別の公開集計結果 |
| Event | 都市史の出来事、日付、分類、説明、課題・政策との関係 |
| CityBenchmark | 比較都市、指標、期間、値、出典、定義の比較可能性 |

政策・予算・成果や都市史・課題の関係には根拠を付けます。単なる同時発生から因果関係を確定しません。
選挙データは記述的・歴史的な研究に限定し、有権者個人の情報や政治的嗜好の推定値を保持しません。

## 公開Webの将来像

| 画面 | 目的 |
|---|---|
| トップ | 人口・経済・財政・暮らしの変化と、主要な問いへの入口 |
| 課題一覧・詳細 | 人口、産業、交通、住宅、教育、子育て、福祉、財政、防災などの整理 |
| 18区ページ | 同じ定義・時点による地域比較と時系列 |
| 予算 | 歳入・会計・部局・事業・支出・成果を追う |
| 意思決定・都市史 | 行政判断や都市の変化を時系列で調べる |
| 選挙史 | 公開集計値を使った歴史的比較 |
| 都市比較 | まず横浜・神戸・福岡を比較する |
| 出典 | 原資料、取得時点、改定履歴、引用箇所を確認する |
| 質問 | 一次情報・数字・時系列・地域比較付きで答える将来機能 |

課題ページは、問題、重要性、事実、推移、原因の仮説、地域差、現行政策、財政影響、成果、他都市、政策の選択肢、反論、未確認事項、出典、変更履歴を整理します。
短い説明から詳細と原典へ進めるようにし、要約でも数値の条件や留保を落としません。

## 公開MCPの方向性

市、区、課題、指標、予算、都市史などをリソースとして参照できるようにします。
ツールは公開情報の検索・取得・比較・検証を対象とし、Webと同じデータを返します。

- 知識: 課題・出典・引用の検索、主張から根拠への追跡。
- データ: 指標と時系列の取得、地域・都市比較。
- 財政・行政: 予算比較、議会記録の検索、意思決定・政策の履歴取得。
- 選挙: 公開結果と投票率の記述的比較。
- 検証: 支持資料・反証資料の検索、資料の鮮度確認。

これらは将来の拡張候補です。現在のツールと接続方法は[MCP手順](runbooks/mcp.md)に記載します。
MCPの仕様・バージョン交渉は採用SDKに従い、初期構想で挙げた日付を仕様保証として固定しません。

## 収集・検証・公開

```text
出典台帳 → 取得 → 原本保存 → 解析 → 定義統一
       → 実体・主張・数値の抽出 → 検査 → 必要な人間レビュー → 公開 → 更新監視
```

原本は上書きせず、同一URLの更新も別の版として保存します。処理は再実行可能にし、欠測、重複、形式変更、参照不整合、過去値の改定を検出します。
確認状態は、未確認・機械確認・人間確認・異議あり・廃止を区別します。機械照合を人間の確認として表示しません。

資料は横浜市・神奈川県・政府統計などの一次資料を優先し、研究機関、報道、企業・団体等の資料は性質を明示します。
出典の権威だけで主張を正しいと判断せず、引用箇所が主張を支えているか確認します。

将来のAI回答は、型付きツールを通してデータを参照し、回答・事実・分析・不確実性・反論・引用を分けて返します。
生成後は別プロセスで主張、引用、矛盾、鮮度を確認します。重要な事実主張すべてに根拠を付けることを目標とし、根拠不足なら未確認とします。
政策・因果説明・法的判断・公式発表・対外回答・財務情報のAI生成文は、人間の承認を経て公開します。

## 品質と運用の目標

- コード: lint、型検査、必要な単体・統合・E2E、依存関係の検査を行います。
- データ: スキーマ、重複、出典、参照整合性、原本との一致を公開前に検査します。
- AI: 導入時に引用・事実性・検索・ツール選択の評価と回帰テストを整備します。
- 運用: 取得失敗や検証失敗を可視化し、問い合わせから参照データ・出典まで追跡できるようにします。
- 設計判断: 重要な判断、理由、見直し条件をADRに残します。

初期構想の性能目安は、公開ページLCP 2秒未満、API p95 300ms未満、検索p95 1秒未満、AIの最初の有用な結果3秒未満です。
可用性の目安はWeb・MCPとも99.9%、原本の喪失と見過ごされた収集失敗を防ぐことです。いずれも測定・運用で確かめる目標であり、現状の保証ではありません。

利用は週次利用者、再訪率、検索成功率、出典への到達、課題の鮮度で評価します。
データは出典数、観測値数、地域範囲、更新状況、確認済み比率を、MCPは成功率、引用率、エラー率、応答時間、費用を追います。

## 長期的なv1の到達条件

現在の人口・世帯の公開β版とは分け、以下を長期的な到達条件とします。

1. 横浜の主要50指標を時系列で取得できます。
2. 18区を同じ指標・定義で比較できます。
3. 主要30課題が根拠付きで整理されています。
4. 全事実から原典の該当箇所へ遡れます。
5. 市の予算・決算を検索できます。
6. 一部の領域で政策・予算・成果を根拠付きで追跡できます。
7. 横浜・神戸・福岡を、定義をそろえて比較できます。
8. AIが横浜について一次情報付きで回答できます。
9. 同じ公開情報と問い合わせ機能をMCPから利用できます。
10. 未公開候補が公開データへ混入しないことを検証できます。
11. AIの事実誤認に対する回帰テストをCIで実行できます。

最初の統合例は、人口変化の問いに対して、公式統計、時系列、18区比較、関連課題、予算、過去政策、他都市比較をつなぎ、検証済みの根拠とともにWeb・MCPへ返す流れです。
市民の操作・理解テストと継続利用の評価は、機能の実装とは別に[開発計画](PLAN.md)の受入条件で確認します。

## 対象外

独自LLM、初期段階の巨大Graph DB、全自治体対応、SNSの網羅的収集は目指しません。
有権者個人DB、政治的嗜好の推定、説得されやすさのスコア、属性別の政治メッセージ最適化は提供しません。
横浜の履歴、構造化データ、地理、政策・予算・成果、引用、人間による確認を深めることを優先します。
