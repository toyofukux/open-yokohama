# 根拠検証の設計判断

2026-09-06。参照先はこの時点で確認した研究・公式文書。非公開会議録や他製品の実装・プロンプトは転載しません。

現在のローカル試作を説明する文書です。追加調査に基づく見直し案は[実装調査](FACT-CHECK-RESEARCH.md)に整理しています。固定3工程や一律の期限が最良と実証されたわけではありません。

## 採用した原則

参考にした助言の要点は、長文を小さな事実へ分ける、一次資料に戻る、複数工程で確認する、分野ごとの基準を整える、確認と修正を分離すること。特定の製品を移植せず、公共統計向けの条件として実装した。

| 判断 | 根拠と実装への適用 |
|---|---|
| 原子的な主張単位 | [FActScore](https://arxiv.org/abs/2305.14251)と[SAFE](https://arxiv.org/abs/2403.18802)の主張分解・根拠評価を参考に、見出しや要約も抽出対象にします。単一の総合点では公開を決めない。 |
| 引用が正しく見えることと、根拠が主張を支えることを分離 | 引用文字列の実在は決定的検査、含意・留保・反証は別のモデル呼び出しで確認します。[引用の正確さと忠実さの研究](https://repository.tudelft.nl/record/uuid%3Abab4a12e-455b-49ea-bdf8-7f6a88478f60)を参照。 |
| 原典集合と分野別基準 | [2026年8月の横断評価](https://arxiv.org/abs/2608.25934)は検索や領域差の問題を扱います。万能な検証器を仮定せず、人口統計の定義・時点・地域・分母・暫定値を明記します。査読前論文を製品精度の保証にはしません。 |
| 判定と人間確認の条件を分離 | 人間確認が必要な主張を別属性にするのは本サイトの設計判断です。[FACTOR](https://arxiv.org/abs/2606.22474)が扱うのは生成の不確実性に応じた検証であり、政策判断の影響度や人間承認の根拠には使いません。 |
| 棄権と反証を残す | 根拠不足と矛盾を分け、前の支持判定を見せない反証工程を置きます。多数決やAIの自己申告した自信で合格にしません。 |
| 版と責任の追跡 | [NIST生成AIリスク管理プロファイル](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence)の測定・記録・監督を参考に、本文・根拠・基準・検証実装の版と承認者区分を固定します。 |

これは2026年9月に利用できる知見を組み合わせた設計であり、「最新モデルなら常に正しい」「すべての領域で最良」という主張ではありません。専門家が検証基準を監修した実績はまだない。

## 実行と境界

[Codexの非対話実行](https://developers.openai.com/codex/noninteractive)を使います。公開原稿と承認した根拠だけをstdinで渡し、構造化出力を厳密に解析します。専用の一時ディレクトリ、読取専用サンドボックス、ツール無効化、環境変数の制限、時間・出力量の上限を組み合わせる。原稿中や資料中の指示はデータとして扱います。

署名済み公開版はWebとMCPで共有します。公開ビルドは秘密鍵なしで検査できる。原典の意味・検索漏れ・モデルの共通誤りは署名で解消しないため、実資料の反例評価と人間のレビューを積み重ねる。

## 評価の区別

- 構造テスト: 改変、欠落、架空引用、判定不一致、反証、期限、承認区分の拒否。検査コードの動作を測る。
- 実記事の検証: 現在の原稿を実資料と照合します。これだけでは一般的な精度を測れない。
- 反例評価: 数値・時点・地域・因果・根拠中の指示などを混ぜた入力への反応を測る。事例数、見逃し、誤拒否を分けて記録します。
- 独立したコードレビュー: 実装者以外が対象版を確認します。政策・統計の専門家による内容承認とは別。

実行していない項目を合格としません。実測結果は[状態記録](STATUS.md)に記します。
