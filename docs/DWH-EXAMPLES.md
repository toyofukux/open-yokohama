# 今あるデータ・記事はどう変わるか

2026-09-07。DWHの目標を具体例で説明します。以下のデータ値は既存ファイルで確認した値です。
「変更後」は今後の実装予定で、まだ提供済みではありません。MCPの公開停止は実施済みです。
詳細なデータ契約は [DWH設計](DWH-DESIGN.md)、現在の管理方法は [監査](DWH-AUDIT.md) を参照してください。

## 「既存3系列」の意味

「系列」は、同じ種類の統計を時系列でまとめたデータのまとまりという意味です。現在は次の3つです。

- **人口・世帯のデータ**：各月1日に何人・何世帯がいるか。人口密度なども含みます。市と18区、2024年1月〜2026年8月を [population.json](../data/published/population.json) に保存しています。
- **人口増減の内訳データ**：一定期間に何人生まれ、亡くなり、転入・転出したか。市の月別は2000年1月〜2026年7月、市と18区の年別は2000〜2025年です。[dynamics.json](../data/published/dynamics.json) に保存しています。
- **年齢別人口のデータ**：各年1月1日に子ども・生産年齢人口・高齢者が何人いるか。年齢不詳と総人口も保持します。市と18区、2000〜2025年を [ages.json](../data/published/ages.json) に保存しています。

「2025年1月1日にいる人数」と「2025年の1年間に増減した人数」は別の値です。
この区別を保ったまま、必要なデータを共通の方法で探せるようにする計画です。

## DWHを何で実装するか

- **保存場所は当面、このリポジトリのファイルです。** 公式CSV等の原本、整理したJSON、出典や定義の台帳をGitで管理します。最初からクラウドの常時稼働DBを契約する計画ではありません。
- **データの整理・計算は更新時に実行します。** 公式資料を取得し、人数や合計を照合して、記事・図表に渡すデータを作ります。ページを開くたびにAIやDWHを動かす構成にはしません。
- **Webには生成済みファイルを渡します。** HTML・図表・JSON・CSVを静的配信します。編集時のAIもまずローカルのデータを参照できるようにし、外部MCPを必要条件にしません。
- **データが増えたら保存技術を見直します。** 原本容量や分析の処理時間を測り、必要になった段階で外部保管やSQLによる分析を検討します。クラウドサービスの選定・追加費用は未決定です。

## 例1：人口と子どもの割合を調べる

- **今**：総人口はpopulation、年齢区分はagesという別ファイル・別形式です。利用側が読み方を知り、同じ地域・基準日の値を選びます。現在の画面にはそのための個別処理があります。
- **変更後**：「横浜市・2025年1月1日・総人口と0〜14歳」を共通の問い合わせで取得できます。3,769,584人と409,362人に、定義・出典・原本行・データ版が付いて戻ります。
- **記事での使い方**：「子どもは約10.9%」を使うと、`409,362 ÷ 3,769,584 × 100` の計算と丸め方も保存します。年齢不詳を含む総人口が分母であることを、本文・図表・注記で共有します。

新しい数字をAIが作るのではなく、既にある数字を、条件と根拠を落とさず組み合わせやすくします。

## 例2：人口増減の記事を作る

- **今**：2025年の人口動態には自然増減−18,732人、社会増減＋18,896人、合計＋164人があります。数値はJSON、説明文の引用・検証は別の文章台帳にあり、記事の入力一式を固定する共通の仕組みがありません。
- **変更後**：「2025年の横浜の人口増減」という記事用に、3つの数値、定義、原典、計算、データ版をひとまとまりに取得します。本文とグラフは同じ参照を使います。
- **読者に見えるもの**：「自然減を社会増が補い、届出による人口増減は年間164人の増加だった」という説明と、その根拠を示す図表・出典です。後に2026年の統計が増えても、この記事の数字は2025年のまま保持します。

このデータだけで「特定の政策が人口を増やした」とは書けません。因果関係には別の根拠が必要です。

## 例3：市が過去の数字を訂正する

- **今**：取得処理は過去値の変更を検出して止まります。その値を使っている記事を一覧で返す機能はありません。
- **変更後**：変更された原本→観測値→割合などの計算→利用記事をたどり、「どの記事・図表を再確認するか」を一覧にします。訂正版を出した後も、元の数字と変更理由を残します。
- **具体的な動き**：仮に2025年の出生数が訂正された場合、出生数の掲載箇所に加え、その値から算出した自然増減や記事も再確認対象にします。これは説明用の仮定で、実際に訂正が発生したという報告ではありません。

## 例4：予算や政策の記事へ広げる

- **今**：人口分野の数字を中心に収録しており、予算・決算・政策の共通台帳はありません。新しい記事で必要になる資料は、その都度調べる必要があります。
- **変更後**：例えば保育の記事なら、子どもの人数、保育施設の定員、対象年度の予算、決定資料を出典付きで接続します。「予算として決まった金額」と「実際に使った決算額」は別データで保存します。
- **数字以外の事実**：「ある事業がいつ決定されたか」も、決定日・決定主体・文書の該当箇所を残します。記事をもう1本書くときも同じ根拠を使えます。施設・予算・決定資料の収録は今後の作業です。

## MCPの公開状態とAPIキー

- **MCPは公開されていました。** 今回、旧公開先のhealthが200で応答し、Cloudflare上でも公開URL・プレビューURLが有効であることを確認しました。
- **AIのAPIキーなしでも動く構成でした。** 現在のMCPは保存済みの統計を返すだけで、AIモデルを呼びません。Cloudflareの管理には別の認証が必要で、この端末には既存のOAuth認証がありました。

- **今後も、キーがあるだけでは公開しません。** ローカルでのデータ利用・検証だけを行います。外部MCPの再開には、ユーザーによる対象・費用条件を含む明示的な再開指示が必要です。

停止方法と確認結果は [MCP手順](runbooks/mcp.md) に記録しました。Cloudflareアカウント全体の費用や契約を停止したという意味ではありません。
