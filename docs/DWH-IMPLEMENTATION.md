# 横浜市DWHの実装と長期記事

2026-09-07。ユーザーの実装指示に基づく、人口分野の最初のDWH実装。
設計全体のうち、数値の共通化・不変版・記事参照・変更影響・利用経路を実装した。
行政文書の文書ファクトの共通移行、財政・他都市比較への拡張は今後の対象。
検証・公開先の最終状態は [STATUS](STATUS.md) に記録する。

## 何が変わったか

- 以前は人口・世帯、人口増減の内訳、年齢別人口の3系列で、それぞれ別の形式を読んでいた。
- 既存16,072値を共通の参照形式へ移し、長期28,566値を追加した。合計44,638値・6系列。
- 地域・時点・定義・基準・単位・値・原典の行列を、一緒に取得できる。
- 観測の論理キーは原典の更新に依存しない。値や原典が変われば別の版IDになる。
- 内容のSHA-256をファイル名にし、同じ版の上書きを拒否する。データ全体の版はmanifestのSHA-256。
- 市と18区の19記事は、本文・図表・計算の入力版を一緒に保存する。過去版を最新値へ自動置換しない。
- 値・出典の変更と削除から、以前のどの記事が影響を受けるかを抽出する。数値改定・削除は理由なしに採用できない。
- 従来の3つのJSON・CSVはDWHから互換出力する。従来の33主張の署名付き記事とは検証範囲を分け、新記事にその署名を流用しない。

## 具体的に読めるようになったこと

横浜市の人口は1995年10月1日の3,307,136人から、2024年10月1日の3,771,063人へ463,927人増えた。
ただし収録した1995年以降の各10月1日では、2020年の3,777,491人が最大で、2024年はそこから6,428人少ない。
「直近の月に何人増えたか」に加え、「長い増加の後に、規模はどう変わっているか」を読める。

同じ期間の世帯数は1,261,330から1,817,762世帯へ増えた。
人口÷世帯数は約2.62人から2.07人へ変化したが、単身世帯数を直接示す値ではない。
港北区では人口279,333→365,316人、金沢区では203,979→193,897人と変化の向きが異なる。
記事は年齢構成、自然増減、社会増減を続けて示し、施設・住宅・移動の需要について次に確認する問いを記述する。
人口の変化だけで、施設不足や政策効果を断定しない。

## 期間の選び方

| 系列 | 収録期間 | 記事での読み方 |
|---|---|---|
| historical | 1920〜2024年、原典掲載年の10月1日 | 市の約100年は歴史的な補足。人口・世帯の主な比較は18区が揃う1995年以降 |
| city-series | 1979〜1999年の10月1日、2000-01〜2026-09の各月1日 | 市全体の月次推移。暫定値への切替を区別 |
| ward-monthly | 2014-06〜2026-09の各月1日、市と18区 | 区の直近の推移。2014年6月より前の月を作らない |
| population | 2024-01〜2026-08の各月1日 | 従来の互換データ。長期系列とは系列名で区別 |
| dynamics | 2000〜2025年、市と18区。市月別2000-01〜2026-07 | 出生・死亡・移動は暦年。初期と直近の5年平均も比較 |
| ages | 2000〜2025年の各1月1日、市と18区 | 年齢構成の人数と割合。分母には年齢不詳を含む |

原典は [横浜市統計書・人口](https://www.city.yokohama.lg.jp/city-info/yokohamashi/tokei-chosa/portal/tokeisho/02.html)。
市域拡張や区再編を補正した固定境界データではない。1945・1991年など掲載のない年を0や補間値にしない。
2025年10月以降の月次は2025年国勢調査速報値に基づく暫定値。
市の2025年9月→10月の残高差−17,480人を、その月の実際の転出超過と説明しない。

## 保存場所と公開境界

| 場所 | 役割 |
|---|---|
| `data/raw/<hash>.csv` / `.xlsx` | 横浜市の数値原典と定義注記。内容hashを検査 |
| `data/catalog/` | 取得先、指標・地域・範囲、原典の基準確認台帳、既知の不一致 |
| `data/candidates/` | 未採用の更新候補。公開・Git追跡から除外 |
| `data/warehouse/objects/<hash>.json` | 正規化観測値、定義、入力metadata、記事、実装hashの不変object |
| `data/releases/<releaseId>/manifest.json` | 使うobjectの組合せを固定 |
| `data/warehouse/changes/` / `runs/` | 差分・影響記事・更新検査の実行記録 |
| `data/published/warehouse.json` | 現行版と採用成功した版の一覧。最後に1ファイルで切替 |
| `data/published/` | 検証付きの互換出力と記事。正本から復元可能 |

候補処理がmanifestを生成しただけでは採用済みにしない。
静的APIは採用成功した版と、そのmanifestから参照するobjectだけを公開する。
取得しただけの原本や、失敗した候補の孤立objectを全列挙して公開しない。

常駐DB・D1・R2・BigQuery・サーバー側AIは追加していない。
原本が10 MB程度になったためADR 0001の見直し条件を確認した。今回の実測は原本約10.5 MB、正規化・記事・履歴約58 MB、静的配布約116 MB。
最大の静的ファイルは約19.9 MB。同一内容のobjectを版ごとに複製せず共有している。
現段階はGitと静的配布を継続し、大規模集計・頻繁な更新・容量増が出たら保存形式や外部保管を別途判断する。

## 編集者の操作

```sh
# 新しい原典を候補として取得。1系列の失敗後も残りを検査する。
pnpm data:refresh:all

# 収録系列・期間を確認
cat data/catalog/warehouse.json

# 市人口の約30年を、出典付きで取得
pnpm dwh:query '{"dataset":"historical","geography":"141003","metric":"population","from":"1995","to":"2024","limit":100}'

# 本文・計算・その入力値・原典を一緒に取得
pnpm dwh:article population-history/yokohama
# 出力: artifacts/warehouse/article.json

# 以前の記事と値を、そのデータ版で再取得
pnpm dwh:article population-history/yokohama --release <releaseId>
pnpm dwh:query '{"dataset":"historical","geography":"141003","metric":"population"}' --release <releaseId>

# 候補の原典・基準・差分を確認した後に採用
pnpm dwh:publish
# 数値改定や削除には実際に確認した理由を記録
pnpm dwh:publish --reason '確認した原典版と改定内容・記事への対応を記述'
pnpm exec tsx scripts/warehouse.ts changes
pnpm verify
```

取得先の変更やAPIキーの存在では、基準確認を省略しない。
`data/catalog/basis-approvals.json` にない原典版は、形式が通っても採用保留になる。
原典の国勢調査基準・速報/確定・年齢推計の注記を確認して台帳を更新する。基準の意味が変わる場合はparser/adapter/記事も更新する。
`--reason` は独立レビューの代わりではない。

## Web・内部MCP

- `/population-history/` と `/population-history/<ward>/`：市と18区の長期記事。
- 従来の区ページ・問いの記事・年齢・動態・ホームから長期記事へ接続。
- `/datasets/`：系列・期間・既知の注意点。
- `/data/warehouse/catalog.json`：指標・原典・期間の共通台帳。
- `/data/warehouse/<dataset>.json`：出典付き観測値。
- `/data/warehouse/articles/<slug>.json`：記事と入力値・計算。
- `/data/warehouse/releases/<releaseId>/manifest.json` と `/data/warehouse/objects/<hash>.json`：過去版。

内部MCPは `pnpm mcp:dev` で `127.0.0.1:8789` に限定。
クラウド認証を使わず、読取専用・毎分60回・同時4件・入力8 KB・応答1 MiB・query最大500値。
既存5ツールに `warehouse_catalog`、`warehouse_query`、`warehouse_article` を追加した。
MCPは現在のバンドル版だけを返し、別のreleaseId指定には未提供を返す。旧版はCLIか静的アーカイブを使う。
外部URL取得、任意SQL、書込み、AI呼出し、外部MCP公開は追加しない。
制限はローカルプロセス単位。クラウド用の分散レート制限として扱わない。

## 失敗時の運用と残る点

- 原本のhash、行列、指標の組合せ、連続性、男女・区の合計、重複期間を検査する。
- 2015年8・9月の市域面積は表2が435.23 km²、表3月次が435.21 km²。相違台帳は双方の原典hashと値を固定し、この2件だけを認識する。正値の確定は未解決。
- 2026年9月の従来人口CSVは密度を小数で掲載し始めたため、従来の整数契約で拒否した。互換系列は8月を維持。長期系列の9月人口は別の統計書から検証して投入済み。
- 同日の更新検査では、動態の8月分10値は未採用の候補として保存。年齢は変化なし。これらを今回の公開値に混ぜていない。
- 通常の公開書込例外では旧版に復元する。故障注入で旧pointerと人口JSONのbyte一致を検査する。
- 強制終了・電源断の場合、複数の互換JSONの同時切替は保証しない。Web/MCPビルドは不一致を検出して停止する。
- 再開時は稼働中のpublishがないことを確認し、残った `data/warehouse/publish.lock` を点検する。停止済みならlockを除去して `pnpm dwh:restore` → `pnpm dwh:check`。検査を外して公開しない。
- 既存3記事のHTML根拠は従来のローカルキャッシュ方式のまま。非公開原本文書の恒久保管は別課題で、今回解決済みとはしない。
