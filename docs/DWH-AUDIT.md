# 数字・ファクト管理の現状監査

調査日: 2026-09-07。対象: `bluegill` の `4926cea` を基準としたローカルのコード・データ・運用文書。
開始時に未commit・未追跡の変更はありませんでした。`main` は同じcommit、`design` は別worktreeです。
目標と移行順は [DWH設計](DWH-DESIGN.md)、今回の検証結果は [STATUS](STATUS.md) に記録します。

## 結論

原本の不変保存、決定的な数値抽出、出典への追跡、公開ゲートは既にあります。
現状は人口分野の公開用データセットを系列ごとに管理する構成です。
横浜の分野横断DWHへ育てるには、共通台帳・改定履歴・記事からの参照契約を追加する必要があります。

open.yokohamaの記事は既にこのリポジトリ内の公開データを読みます。
別サイトとの連携を新設する話ではなく、既存の利用を記事作成・調査・更新判断へ広げる位置づけです。

## 1. 数字の棚卸し

値数はローカルの `data/published/` を集計しました。指標数は実装上のID数です。
総人口のように系列間で意味が重なる指標を含むため、24種類の独立した社会指標という意味ではありません。

| 系列 | 収録範囲 | 構造・値数 | 原本・正本 |
|---|---|---|---|
| 人口・世帯・面積等 | 市と18区、2024-01-01〜2026-08-01、32時点 | 9指標、5,472観測値。1行に1指標 | 32 CSV、[population.json](../data/published/population.json)、[定義・契約](../packages/core/schema.ts) |
| 人口動態 | 市の月別2000-01〜2026-07、市と18区の暦年2000〜2025 | 10指標、月別3,190＋年別4,940＝8,130観測値 | 3 CSV、[dynamics.json](../data/published/dynamics.json)、[定義・契約](../packages/core/dynamics.ts) |
| 年齢構成 | 市と18区、2000〜2025年の各1月1日 | 494レコードに5指標、2,470値。各歳原本から3区分等へ集計 | 1 CSV、[ages.json](../data/published/ages.json)、[定義・契約](../packages/core/ages.ts) |
| 動態の定義・訂正注記 | 表8のExcel | 数値データとは別の参照記録 | 1 XLSX、[注記台帳](../data/references/dynamics-notes.json) |

合計は3系列・24指標ID・16,072値です。予算・決算・政策・施設・他都市の構造化データは未収録です。
保存原本は36 CSV＋1 XLSX＝37ファイル、7,862,238 bytes（約7.86 MB）、取得manifestは5ファイルです。
これは現worktreeのファイル量で、Git履歴全体や将来容量の見積もりではありません。

### 保持できている条件

- 観測時点、地域コード、値、出典ハッシュ、行・列、改定番号、機械確認状態があります。年齢集計は全入力行を保持します。
- 出典には原典URL、掲載ページ、取得日、提供者、利用条件、パーサー版があります。現データの `publishedAt` はnullです。
- 数字はLLMで抽出せず、型・男女計・市区計・年/月計・算術・原本再解析で検査します。現在の改定番号は全件1です。
- 人口残高、暦月・暦年の届出増減、各年1月1日の年齢構成を区別します。不詳を配分せず、未提供を0にしません。

検査の実装は [人口](../scripts/validate.ts)、[動態](../scripts/validate-dynamics.ts)、[年齢](../scripts/validate-ages.ts) です。

## 2. 文章・ファクトの棚卸し

| 対象 | 現在の正本・検査 | 再利用上の制約 |
|---|---|---|
| 人口・世帯・密度の3記事 | [原稿](../data/editorial/issues.json) → 主張抽出・根拠照合・反証 → [署名済みレビュー](../data/editorial/review.json) → [公開文章](../data/published/editorial.json) | 原稿schemaは3指標と6文章欄を前提。一般記事や政策資料の契約へは未拡張 |
| 記事の根拠資料 | [evidence.json](../data/editorial/evidence.json) に15件。公式HTML 6、人口CSV 2、内部実装7 | 数値のsnapshot台帳と別ID体系。内部実装は製品機能の根拠で、横浜の外部事実の根拠ではない |
| 抽出された主張 | 33件（fact 28、non_assertion 5）。原稿欄と支持・反証の引用文字列に接続 | 記事・レビュー内のIDであり、記事をまたぐ安定したファクト台帳ではない |
| 記事内の数値 | [記事テンプレート](../apps/web/src/pages/issues/[slug].astro) が `fact()` で公開JSONの最新値を取得 | 文章レビューの版とは別に、ビルドで最新時点が選ばれる。記事ごとの参照データ固定はない |
| グラフの解説・地域本文 | [chart-insights.ts](../packages/core/chart-insights.ts)、[region-story.ts](../packages/core/region-story.ts) で公開値から計算 | 数式・条件のテストと実装レビューが対象。3記事のAI署名の対象ではない。計算結果の共通ID台帳はない |
| 訂正 | GitHub Issues受付＋[訂正台帳](../data/corrections/records.json)。現台帳は0件 | `/issues/` の記事単位の保留。観測値・原典から利用記事を逆引きする台帳はない |

HTMLは抽出本文とハッシュをGitに保持し、原本HTMLはGit対象外のローカルキャッシュです。
このworktreeの調査開始時にはキャッシュがありませんでした。
[復元処理](../scripts/factcheck-cache.ts) は元URLから同じ原本を再取得するため、原典変更・消失で再現が止まります。
CSVの長期保存と、文章根拠の原本を復元できる保証は同じではありません。

## 3. 更新・問い合わせ・公開

| 観点 | できていること | DWHとして残ること |
|---|---|---|
| 取得 | 3つの取得script。原本ハッシュ保存、形式異常・過去値変更・削除を拒否 | 横断的な資料台帳、取り込みrun台帳、系列ごとの最終確認・更新予定・失敗状況 |
| 正本と公開物 | `data/published/` がWeb・MCPの共通入力 | 正規化された正本と公開用の集計・配布物が同じ層。新期間の正常取得はローカルのpublishedを更新する |
| 版 | Git、原本ハッシュ、`revision`、生成日時 | population/dynamicsの観測IDは原本ハッシュを含み、資料更新で変わる。agesは共通の観測IDを返さない。全系列を束ねるrelease IDはない |
| 再現 | 保存CSVと同じcommitから数値を再生成可能 | 記事公開時の指標定義・計算・入力値を一括で指定して取得する契約、旧版の公開取得経路 |
| Web・JSON・CSV | 3系列を配布。画面はcoreの定義・計算を利用 | 人口JSONに指標定義が同梱されないなど、系列ごとに配布契約が異なる |
| MCP | [5ツール](../apps/mcp/src/index.ts)で指標・推移・区比較・出典・検索。記事resourceもある | 期間範囲・release指定、一般ファクト・引用の取得、引用用のまとまった出力がない |
| 出典検索 | MCPの `get_source` は現在の3系列のCSV snapshotを解決 | HTML根拠・Excel注記・過去版を統一して解決しない。`search` は地域・定義・記事の文字列検索 |
| 更新監視 | [週次Actions](../.github/workflows/refresh.yml)で検査、失敗表示、候補artifactを30日保存 | 先行stepの失敗で後続系列の検査が止まる。期限到来時の公開文章の自動撤回や、根拠更新からの記事再確認はない |

同じcommitからWeb・MCPを出す運用はありますが、別デプロイの切替を原子的に揃える仕組みではありません。
今回、本番ページと配布JSONは取得時にHTTP 403でした。本番の内容一致・稼働不良のどちらも、この結果だけでは判定しません。
公開記録は既存の [STATUS](STATUS.md)、今回の監査根拠はローカルの実データ・コードです。

## 4. 優先して埋める差分

| 優先 | 差分 | 記事・調査への影響 | 設計での対応 |
|---|---|---|---|
| 1 | 指標・出典・観測IDと配布契約が系列別 | 指標を増やすたびに利用側が個別対応する | 共通カタログ・論理キー・版ID・互換adapter |
| 1 | 記事の入力値・計算式・根拠版がまとまっていない | 過去記事の再現や再利用が難しい | 引用用データと記事依存台帳、記事版の固定 |
| 1 | 文書原本の保全がキャッシュ依存 | 原典改定後に既存検証を再現できない場合がある | 利用条件を持つ原本台帳、公開可否を分けた保全・復元 |
| 2 | 出典更新と記事への影響が接続されていない | 訂正漏れ・古い説明の残存を把握しにくい | 変更→観測/ファクト→計算→記事の逆引き |
| 2 | 基準日・定義・地域の版が共通化されていない | 財政・施設・都市比較で誤結合しやすい | 時間・地理・統計系列・定義版の共通契約 |

既存文書にも更新漏れがありました。データ更新手順の「年齢別人口は未収録」を修正し、次の着手順をDWH設計へ接続します。
過去の実装・レビュー記録は履歴として残し、当時の未提供事項を現在の状態として案内しません。
